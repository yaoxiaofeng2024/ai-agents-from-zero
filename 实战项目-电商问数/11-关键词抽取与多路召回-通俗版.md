# 第十一章（通俗版）：关键词抽取与三路召回

---

## 一、这一章在做什么？

上一章搭好了工作流骨架，这一章开始填业务逻辑。要实现四个节点：

```text
extract_keywords  → 从用户问题里抽关键词
recall_column     → 根据关键词召回字段信息
recall_metric     → 根据关键词召回指标信息
recall_value      → 根据关键词召回字段真实取值
```

以"统计华北地区的销售总额"为例：

| 用户说的 | 属于什么 | 系统要做什么 |
|---------|---------|------------|
| "销售总额" | 指标 | 找到 GMV 的定义和依赖字段 |
| "华北地区" | 字段取值 | 确认库里存的是"华北" |
| "地区" | 字段 | 找到 region_name 字段 |

---

## 二、三路召回分别解决什么？

| 召回链路 | 解决的问题 | 用什么技术 | 通俗理解 |
|---------|-----------|-----------|---------|
| 字段召回 | "地区"像哪个字段？ | Qdrant 向量检索 | 找"查哪一列" |
| 指标召回 | "销售总额"像哪个指标？ | Qdrant 向量检索 | 找"怎么算" |
| 字段取值召回 | "华北"在库里真实值是什么？ | ES 全文检索 | 找"条件值怎么写" |

**字段和指标用向量检索**——因为主要匹配语义相似（"销售额"和"GMV"字面不同但意思接近）。

**字段取值用全文检索**——因为更关注真实文本命中（"华北"是不是库里存在的值）。

## 三、关键词抽取：用 jieba 分词

`extract_keywords` 节点做的事：

```text
读取用户问题
  → jieba 提取关键词（按词性过滤）
  → 把原始问题也加入关键词（兜底）
  → 去重
  → 返回 {"keywords": [...]}
```

### 为什么做词性过滤？

关键词是拿去做检索的，不是做文本展示。"的""帮我""一下"这类没有业务价值的词放进去只会增加噪声。

项目保留的词性：名词、地名、动词、英文、固定短语等。

### 为什么要把原始问题也加进去？

兜底策略。如果分词漏掉了重要表达，完整问题仍然可以作为检索入口。

```python
keywords = list(set(keywords + [query]))
```

## 四、关键词扩展：让大模型帮忙补充

三路召回之前，都会让大模型做一件事：**根据用户问题，生成一组更适合检索的业务短语。**

比如用户问"统计华北地区的销售总额"，模型可能扩展出：
- 字段方向：金额、订单金额、地区名称
- 指标方向：GMV、成交额、交易额
- 取值方向：华北、华南、华东

### LCEL 最小链路

```text
PromptTemplate → LLM → JsonOutputParser
```

- PromptTemplate：组装提示词
- LLM：调用大模型
- JsonOutputParser：把输出解析成 JSON

---

## 五、字段召回和指标召回：同一套模式

两路召回的流程完全一样：

```text
扩展关键词
  → 每个关键词用 Embedding 转成向量
  → 去 Qdrant 搜索最相似的点
  → 拿到 payload（字段/指标的完整信息）
  → 去重
  → 返回召回结果
```

区别只在于：
- 字段召回查 `column_info_collection`
- 指标召回查 `metric_info_collection`

---

## 六、字段取值召回：用 ES 的模式

```text
扩展关键词
  → 每个关键词去 ES 搜索
  → 拿到匹配的文档（包含 column_id 和 value）
  → 去重
  → 返回召回结果
```

和前两路的核心区别：**不用 Embedding 转向量，直接用关键词做全文检索。**

## 七、State 和 Context 的分工

### State：保存业务中间结果

```python
class DataAgentState(TypedDict):
    query: str
    keywords: list[str]
    retrieved_column_infos: list[ColumnInfo]
    retrieved_metric_infos: list[MetricInfo]
    retrieved_value_infos: list[ValueInfo]
    error: str
```

### Context：保存运行时工具

```python
class DataAgentContext(TypedDict):
    column_qdrant_repository: ColumnQdrantRepository
    embedding_client: HuggingFaceEndpointEmbeddings
    metric_qdrant_repository: MetricQdrantRepository
    value_es_repository: ValueESRepository
```

**State 放"数据"，Context 放"工具"。**

## 九、本章要点速记

| 要点 | 一句话 |
|------|--------|
| 三路召回 | 字段找"查哪列"，指标找"怎么算"，取值找"条件怎么写" |

| 取值召回 | 关键词 → ES 全文检索 → 去重 |
| State vs Context | State 放业务数据，Context 放运行时工具 |
