# 前言（通俗版）：欢迎来到「电商问数」

---

欢迎来到「电商问数」项目！这是「AI 智能体实战速成指南」的实战部分。

如果你正在找一个**真正能学到东西**的 AI 项目——不是只调一次大模型接口、写几个 Prompt、演示一下 SQL 生成就完事的那种——那这套教程非常适合你。

---

## 先说结论：这个项目到底在干嘛？

一句话：**用户用自然语言提问，系统自动查数据库，把结果返回给你。**

比如你问："华北地区的销售总额是多少？"系统会自动：
1. 理解你的问题
2. 找到该查哪些表、哪些字段
3. 生成 SQL
4. 执行查询
5. 把结果展示给你

听起来简单？但真正做起来，中间要解决的问题可不少。

---

## 为什么这个项目值得学？

很多 AI 教程容易走两个极端：

| 极端 | 问题 |
|------|------|
| **太轻** | 只演示一次模型调用，学完不知道怎么做真实项目 |
| **太重** | 一上来就塞进大量生产级能力，新手容易迷失 |

「电商问数」走的是中间路线：**保留真实系统最核心的工程链路，但不一开始追求大而全。**

你会看到这些问题为什么必须解决：

- 面对多张表，系统怎么知道该查哪张？
- 用户说"华北"，系统怎么知道数据库里存的是"华北"还是"华北地区"？
- 为什么不能让大模型直接写 SQL，而要先检索、再生成？
- SQL 生成后为什么还要校验？
- 后端为什么要用流式返回？

**你不是在孤立地学一个数据库、一个向量库、一个框架，而是在学习它们如何配合完成一个真实的智能体应用。**

---

## 这个项目用到了哪些技术？

别被技术栈吓到，先看它们各自解决什么问题：

| 技术 | 一句话解释 | 在项目里的角色 |
|------|-----------|--------------|
| **MySQL** | 存数据的数据库 | 模拟数仓 + 保存元数据 |
| **Qdrant** | 向量数据库 | "语义上谁更像"——用户说"销售额"，能找到"订单金额" |
| **Elasticsearch** | 全文检索引擎 | "文本上能不能匹配"——用户说"华北"，能确认库里确实有这个值 |
| **LangGraph** | 工作流编排框架 | 把多个步骤串成一条可控的流水线 |
| **FastAPI** | 后端 Web 框架 | 提供接口，让前端能调用 |
| **SSE** | 流式推送技术 | 让前端实时看到执行进度 |

把它们串起来就是：

```text
用户提问 → LangGraph 编排工作流 → Qdrant/ES 检索上下文 → 大模型生成 SQL → MySQL 执行 → SSE 推送结果
```

## 这套教程的亮点：跟着代码分支一步步来

这套教程不只是"最终代码 + 一篇说明文档"。每个关键章节都有对应的代码分支。

也就是说，你可以按章节一步一步切换代码：

| 阶段 | 章节 | 你会做什么 |
|------|------|-----------|
| 基础准备 | 第3-6章 | 搭环境、接服务 |
| 知识库构建 | 第7-9章 | 把元数据整理成可检索的知识 |
| 智能体搭建 | 第10-14章 | 逐步搭问数工作流 |
| 接口交付 | 第15-17章 | 把能力通过 API 交给前端 |

**真正难的不是"看懂最终项目里有哪些文件"，而是知道这些文件是怎么一步步长出来的。**

## 这个项目适合学什么，不适合学什么？

### 适合学的

- MySQL 在分析场景里怎么用
- 向量检索和全文检索分别解决什么问题
- 智能体工作流怎么编排
- 后端接口怎么和前端联调
- 工程分层（配置、客户端、仓储、服务、节点）怎么组织

### 不刻意覆盖的

- 用户权限和数据权限控制
- 多租户隔离
- 查询缓存和性能治理
- 完整评测体系
- 监控告警和生产部署

这些能力当然重要，但全部放进第一个项目里，主线反而会被淹没。**先把最关键的主链路跑通，讲透，比什么都重要。**

## 项目目录结构速览

不用记住每个目录，先有个印象就行：

```text
shopkeeper-agent/
├── app/                  # 后端源码
│   ├── agent/            # 智能体（LangGraph 工作流）
│   ├── api/              # 接口层（FastAPI 路由）
│   ├── clients/          # 基础服务客户端（MySQL、ES、Qdrant、Embedding）
│   ├── conf/             # 配置加载
│   ├── core/             # 日志、生命周期等通用能力
│   ├── entities/         # 业务实体
│   ├── models/           # ORM 模型
│   ├── repositories/     # 数据访问层
│   ├── scripts/          # 工具脚本（构建知识库等）
│   └── services/         # 业务逻辑层
├── conf/                 # YAML 配置文件
├── docker/               # Docker 相关文件
├── frontend/             # 前端项目
└── prompts/              # 提示词文件
```

```text
项目概述与数仓基础 → 整体架构 → 环境准备 → 元数据知识库 → 问数链路 → API接口与联调
```
