## 一、项目目录结构：先知道东西放哪

不用记住每个目录，先知道"哪类东西放哪"就行：

```text
shopkeeper-agent/
├── app/                  # 所有源码都在这里
│   ├── agent/            # 智能体相关（LangGraph 工作流）
│   ├── api/              # 接口层（FastAPI 路由）
│   ├── clients/          # 基础服务客户端（MySQL、ES、Qdrant、Embedding）
│   ├── conf/             # 配置加载
│   ├── core/             # 通用能力（日志、生命周期等）
│   ├── entities/         # 业务实体
│   ├── models/           # ORM 模型（对应数据库表）
│   ├── repositories/     # 数据访问层
│   ├── scripts/          # 工具脚本
│   └── services/         # 业务逻辑层
├── conf/                 # YAML 配置文件
├── docker/               # Docker 相关
├── frontend/             # 前端项目
└── prompts/              # 提示词文件
```

**核心原则：源码放 `app`，配置放 `conf`，提示词放 `prompts`。**

如果你做过 Java/Spring Boot，可以这样类比：

| Python 项目 | Java 项目 |
|------------|----------|
| api | controller |
| services | service |
| repositories | mapper/repository |

## 二、配置管理：为什么不能把参数写死在代码里？

想象一下：MySQL 的地址、密码、ES 的端口、大模型的 API Key……如果全写死在代码里：

- 换个环境就要改代码
- 密码泄露到代码仓库
- 配置和逻辑混在一起，很难维护

**所以更合理的做法是：把配置写到 YAML 文件里，代码从文件里读。**

### 配置文件长什么样？

`conf/app_config.yaml` 的核心内容：

```yaml
db_meta:          # 元数据库
  host: localhost
  port: 3306
  user: didilili
  password: dili123
  database: meta

db_dw:            # 数仓模拟库
  host: localhost
  port: 3306
  user: didilili
  password: dili123
  database: dw

qdrant:           # 向量数据库
  host: localhost
  port: 6333
  embedding_size: 1024

es:               # 全文检索
  host: localhost
  port: 9200
  index_name: data_agent

llm:              # 大模型
  model_name: gpt-5.2-codex
  api_key: <api_key>
  base_url: https://api.openai-proxy.org/v1
```

### YAML 是什么？

YAML 就是一种配置文件格式，比 JSON 更简洁：

| JSON | YAML |
|------|------|
| `{"name": "zhangsan", "age": 18}` | `name: zhangsan`<br>`age: 18` |
| `["a", "b", "c"]` | `- a`<br>`- b`<br>`- c` |

**JSON 更像数据交换格式，YAML 更像工程配置格式。**

> 注意：YAML 对缩进非常敏感，层级靠缩进表达，对齐错了就解析出错。

## 三、配置怎么加载到代码里？

流程很简单：

```text
YAML 文件（配置值）
  + dataclass 类（配置结构）
  → OmegaConf 合并
  → 配置对象（代码里直接用 app_config.xxx 访问）
```

### 代码里的配置结构

每个配置分组对应一个 dataclass：

```python
@dataclass
class DBConfig:        # 数据库配置
    host: str
    port: int
    user: str
    password: str
    database: str

@dataclass
class QdrantConfig:    # 向量库配置
    host: str
    port: int
    embedding_size: int

@dataclass
class AppConfig:       # 总配置入口
    logging: LoggingConfig
    db_meta: DBConfig
    db_dw: DBConfig
    qdrant: QdrantConfig
    embedding: EmbeddingConfig
    es: ESConfig
    llm: LLMConfig
```

### 加载过程

```python
# 1. 读取 YAML 文件
context = OmegaConf.load(config_file)

# 2. 根据 AppConfig 生成结构
schema = OmegaConf.structured(AppConfig)

# 3. 合并结构 + 值，变成可直接访问的对象
app_config = OmegaConf.to_object(OmegaConf.merge(schema, context))
```

加载完成后，代码里就可以这样用：

```python
app_config.es.host       # → "localhost"
app_config.db_meta.port  # → 3306
```

## 四、路径问题：为什么不能写死相对路径？

```python
# 不推荐：依赖启动目录
OmegaConf.load("conf/app_config.yaml")

# 推荐：基于当前文件位置找
config_file = Path(__file__).parents[2] / "conf" / "app_config.yaml"
```

原因：相对路径依赖"程序从哪个目录启动"，换个地方启动就找不到文件了。`__file__` 是当前 Python 文件自身的路径，基于它去找配置文件更稳定。

## 六、本章要点速记

| 要点 | 一句话 |
|------|--------|
| 项目结构 | 源码放 app，配置放 conf，提示词放 prompts |
| 配置管理 | YAML 存值，dataclass 存结构，OmegaConf 负责合并 |
| 路径问题 | 用 `Path(__file__)` 而不是写死相对路径 |
| 配置驱动 | 代码只管"怎么做"，配置决定"做哪些" |
