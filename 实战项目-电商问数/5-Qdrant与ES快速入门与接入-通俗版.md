# 第五章（通俗版）：Qdrant 和 ES——两种不同的"找东西"方式

---

## 一、为什么需要两个检索工具？

很多人第一次看到项目时会问：**既然都是"检索"，为什么还要同时用 Qdrant 和 Elasticsearch？**

答案很简单：**它们解决的不是同一类问题。**

| 工具 | 擅长什么 | 在项目里干什么 |
|------|---------|--------------|
| **Qdrant** | 语义相似度——"意思像不像" | 用户说"销售额"，能找到"订单金额" |
| **Elasticsearch** | 文本匹配——"字面上有没有" | 用户说"华北"，能确认库里确实有这个值 |

> 打个比方：Qdrant 像"你描述个大概，我帮你找到最接近的"，ES 像"你说个精确词，我帮你确认在不在"。

## 二、Qdrant：向量数据库入门

### 2.1 什么是向量数据库？

传统数据库按"行和列"存数据，向量数据库按"向量点"存数据。

| 数据库类型 | 存什么 | 擅长什么 |
|-----------|--------|---------|
| OLTP（如 MySQL） | 行记录 | 精确查询某一行 |
| OLAP（如 Hive） | 列数据 | 统计分析某一列 |
| 向量数据库（如 Qdrant） | 向量点 | 语义相似度检索 |

### 2.2 Qdrant 的四个核心概念

| 概念 | 通俗解释 | 项目里对应什么 |
|------|---------|--------------|
| **Collection** | 一组向量的集合，类似数据库的"表" | `column_info_collection`（字段专用） |
| **Point** | 集合里的一条记录 | 一个字段的一个语义入口 |
| **Vector** | 一串数字，是文本经过 AI 编码后的结果 | 把"销售额"变成 `[0.12, -0.08, ...]` |
| **Payload** | 跟向量一起存的业务数据 | 字段的完整信息（名称、描述、所属表等） |

一个 Point 长这样：

```json
{
  "id": "column-001",
  "vector": [0.12, 0.98, 0.44, 0.31],
  "payload": {
    "name": "region_name",
    "description": "地区名称"
  }
}
```

### 2.3 Qdrant 的基本操作

就四步：

```text
初始化客户端 → 创建 Collection → 写入 Points → 查询相似向量
```

对应的关键 API：

| API | 做什么 |
|-----|--------|
| `create_collection()` | 创建集合，声明向量维度和距离度量 |
| `upsert()` | 按 id 更新或插入 points |
| `query_points()` | 根据查询向量返回最相关的点 |

### 2.4 项目里怎么封装的？

项目没有在每个地方都临时创建客户端，而是统一封装了 `QdrantClientManager`：

```text
QdrantClientManager 做的事：
  - 保存配置（host、port）
  - init()：创建异步客户端
  - close()：关闭连接
  - 全局单例，其他模块复用同一个客户端
```

> 为什么用异步客户端？因为 Qdrant 读写是网络 I/O，异步可以在等待响应时让出 CPU，提高并发。

## 三、Elasticsearch：全文检索入门

### 3.1 ES 在项目里干什么？

ES 不替代 MySQL，也不替代 Qdrant。它的职责很明确：

**把字段的真实取值建索引，让系统能确认"用户说的值在库里到底有没有"。**

比如用户说"华北地区"，SQL 里需要写 `WHERE region_name = '华北'`。但如果库里存的是"华北"而不是"华北地区"，SQL 就查不到数据。

ES 就是帮系统确认：**过滤条件里的值应该写成数据库里真实存在的样子。**

### 3.2 ES 的核心概念

| 概念 | 通俗解释 | 项目里对应什么 |
|------|---------|--------------|
| **Index** | 类似数据库的"表" | `data_agent` |
| **Document** | 类似表里的"一行" | 一个字段取值记录 |
| **Mapping** | 类似表的"结构定义" | 定义字段取值文档有哪些字段 |

### 3.3 ES 的基本操作

```text
初始化客户端 → 创建 Index（定义 Mapping）→ 写入 Documents → 搜索
```

### 3.4 项目里怎么封装的？

和 Qdrant 一样，ES 也封装了 `ESClientManager`：

```text
ESClientManager 做的事：
  - 保存配置（host、port）
  - init()：创建异步客户端
  - close()：关闭连接
  - 全局单例
```

## 四、Qdrant vs ES：什么时候用哪个？

| 场景 | 用什么 | 原因 |
|------|--------|------|
| 用户说"销售额"，要找对应字段 | Qdrant | "销售额"和"订单金额"字面不同，但语义相似 |
| 用户说"华北"，要确认库里有没有这个值 | ES | 需要精确匹配文本 |
| 用户说"GMV"，要找对应指标 | Qdrant | "GMV"和"成交额"语义相似 |

**一句话：找"像什么"用 Qdrant，找"有没有"用 ES。**

## 五、本章要点速记

| 要点 | 一句话 |
|------|--------|
| Qdrant | 向量数据库，解决"语义上谁更像" |
| Elasticsearch | 全文检索，解决"文本上能不能匹配" |
| Collection / Index | Qdrant 的"表"叫 Collection，ES 的"表"叫 Index |
| Point / Document | Qdrant 的一条记录叫 Point，ES 的叫 Document |
| 异步客户端 | 项目用 AsyncQdrantClient 和 AsyncElasticsearch，提高并发 |
| 客户端封装 | 统一管理初始化和关闭，全局单例复用 |
